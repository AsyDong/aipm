## 二、生产环境变量（`.env.production`）

```
# 出题走本地：题库是程序化生成的，远端绕一圈没有收益，还多一个失败面
VITE_API_BASE_URL=
VITE_PREFER_REMOTE=0

# 同步走同域（nginx 反代到 127.0.0.1:8787）；令牌必须与服务器 SYNC_TOKEN 一致
```

> ⚠️ `VITE_` 开头的变量会被打进前端 bundle，等同半公开凭证 —— 它只够写 `/api/sync`，

## 四、ICP 备案（境内服务器必须，OPS 前置）

**为什么必须做**：服务器在境内（腾讯云），未备案的域名用 80/443 对外提供网站服务会被拦截。
备案通过前，`https://petkitchen.com` 打不开 —— 这一步是**时间上的关键路径**（通常 1~20 个工作日），建议**尽早提交**。

**需要你提供的信息**（我这边无法代办）：

| 项 | 说明 |
|---|---|
| 主体类型 | 个人 / 企业（个人可用，但部分省份要求网站名与主体相关） |
| 主体证件 | 身份证 / 营业执照 + 法人身份证 |
| 负责人手机号 + 邮箱 | 用于核验与接收通知 |
| 应急联系电话 | 备案要求填写 |
| 域名证书 | 域名注册商控制台可下载 |
| 服务器实例 | 备案服务号（腾讯云控制台 → 备案 → 用本台轻量实例申请） |
| 网站名称 | 建议「小小闯关家」这类中性名，不要含「教育」等需前置审批的词 |
| 网站服务内容 | 选「其他」，描述写「家庭教育辅助工具」 |

> 提示：个人备案的通过率取决于省份。若走企业主体，通过更快、后期也不用改。
> 备案信息里的网站内容描述**不要**出现「在线教育」「培训」等字眼 —— 可能被要求补前置审批。

### 4.1 合规边界：个人主体能不能「线下收费 + 控制网站可用性」

**结论：不行，这条路走不通，而且风险远大于收益。** 判定「经营性 / 非经营性」看的是**商业实质**，不是收款渠道。

| 你想的做法 | 实际定性 | 风险 |
|---|---|---|
| 线下/微信收款，换取网站访问权（激活码、账号白名单、付费解锁） | 属于「**向上网用户有偿提供信息服务**」→ **经营性** | 个人主体无法办 ICP 许可证 → 无证经营 |
| 网页上不写价格，只做「扫码咨询 / 加微信」引流，在线下成交 | 同上（**引流本身已是个人备案明确禁区**） | 备案直接驳回；已备案的会被注销 |
| 挂打赏码、广告位（哪怕零星） | 视收入性质可能被认定经营性 | 若为主营收入则构成经营性 |
| 纯免费、无广告、无付费入口 | 非经营性 ✅ | 个人备案正常适用 |

**处罚依据**（《互联网信息服务管理办法》第十九条）：未取得经营许可证擅自从事经营性互联网信息服务的，责令限期改正，**没收违法所得 + 处违法所得 3~5 倍罚款**；无违法所得或不足 5 万元的，**处 10 万~100 万元罚款**；情节严重的**责令关闭网站**。
（2025 年 4 月陕西通管局实例：某公司无证经营，没收违法所得 12.4 万 + 罚款 62 万。）

**另外两个叠加风险**：

1. **备案核验本身就过不去**。管局与接入商要求网站可正常访问、且内容与备案填报一致。做成「仅付费用户可用」的封闭站，首次核验就难以通过；事后抽查发现「备案信息与实际内容不符」会被**取消接入、注销备案**。
2. **本项目还叠加儿童合规**。收费会引入未成年人付费保护、发票/退款义务、儿童个人信息（PIPL 第 31 条需监护人同意）等要求 —— 这些在免费公益工具形态下门槛低得多。

**可行的三条路径**（按推荐度）：

| 路径 | 适用 | 要点 |
|---|---|---|
| **A. 免费 + 企业主体备案**（推荐） | 想长期做，但暂不收费 | 企业营业执照备案，名称可正常起；保持无付费入口，仍算非经营性，**不需要 ICP 许可证** |
| **B. 企业主体 + ICP 许可证** | 确定要收费变现 | 纯内资公司、注册资本 ≥100 万（认缴）、经营范围含「增值电信业务」、≥3 名员工社保、先完成 ICP 备案 → 审批 40~60 工作日 |
| **C. 中国香港/境外服务器免备案** | 只做小范围测试 | 免备案，但国内直连慢、微信内打开易被拦、不稳定；且「向内地提供服务」仍属灰色地带，**不适合面向国内家长正式运营** |

**如果只是想先在小范围（亲友、家长群）试**：保持**免费、不公开推广、不以此为营生**，可以个人备案先跑起来；但**不要**出现打赏码、广告位、「扫码购买/咨询」入口，也不要公开宣传收费 —— 一旦公开商业化，就落回上表的经营性区间。

> ⚠️ 以上是基于现行法规与公开处罚案例的工程侧判断，**不构成法律意见**。涉及收费前的最终定性，建议向腾讯云备案客服或当地通信管理局咨询确认。

### 4.2 「社群收费 + 咨询收费，网站免费给成员用」这个结构行不行

**比 4.1 的「付费换访问权」合理得多 —— 核心区别是：你卖的是真实独立的服务（社群运营、一对一咨询），网站只是附带工具，而不是「拿网站本身卖钱」。** 这个结构可以成立，但有三条硬边界必须守住。

**为什么这次站得住**：网站自身**无偿、公开、无付费入口** → 定性为非经营性 ✅；收入对应的是社群运营与人工咨询服务（有真实交付、有服务记录），不是「信息服务费」。监管区分的是「卖信息服务」还是「卖别的服务、网站只是个工具」。

| 做法 | 判定 | 说明 |
|---|---|---|
| 网站纯免费工具，社群里口头/私下告知网址 | ✅ **可行** | 网站非经营性，个人备案适用；社群与咨询属线下经营，另行依法纳税 |
| 网站上出现「加入社群」「扫码进群」「咨询我们」「联系我们」入口 | ⚠️ **中高风险** | 构成「通过网站招揽客户、促成付费交易」，可能被纳入经营性；且是个人备案**明确禁区**，备案直接驳回 |
| 网站放价格表 / 购买按钮 / 打赏码 / 广告位 | ❌ **经营性** | 回到 4.1，无证经营 |
| 服务只能在网站上交付（群内资料必须登录网站才看得到） | ⚠️ **灰色** | 形式上仍是「付费换访问权」，有被穿透认定的风险 |

**三条硬边界**：

1. **网站上不出现任何商业化入口**。不能有「加群、咨询、购买、打赏、广告」字样或二维码。域名只通过社群内部渠道（群公告、私聊）告知 —— 这是整个结构成立的**前提**。
2. **备案填报必须与网站实际一致**。网站如实描述为「个人家庭教育辅助 / 记录工具」，名称用中性词；**不要**写成「XX 社群官方站」「XX 咨询」之类，也不要在服务内容里选与教育/咨询相关的类目。
3. **钱要有对应的真实交付**。社群服务、咨询记录留痕（聊天记录、咨询纪要），收入依法申报纳税。收费规模稳定后，建议注册个体工商户或公司——顺带把备案主体切成企业，一举两得。

**两个额外提醒**：

- ⚠️ **若「咨询」涉及投资理财建议**，属**持牌业务**（证券投资咨询需相应资质），不能用个人社群名义开展。育儿/教育方向的咨询不受此限，但不要声称「专业指导」「诊断」等。
- 面向家长收费即面向未成年人相关服务，**未成年人付费需监护人同意**；儿童个人信息（PIPL 第 31 条）仍需监护人单独同意。

**落地建议**：网站维持纯工具形态（保留一个非商业的「问题反馈邮箱」即可），社群与咨询走线下/微信、单独收款、单独记账。这样网站能稳定通过个人备案，变现也不用等，两条线互不干扰。
