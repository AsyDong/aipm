# 萌宠打卡 App · 开发交付说明 v1.0

> 面向深圳 1–2 年级孩子的「打卡养宠 + 闯关练题」Web 应用
> 技术栈：Vite 5 + React 18 + TypeScript（strict）+ Tailwind CSS 3 + zustand（persist）
> 源码规模：36 个文件 / 约 4,400 行 TS·TSX，零后端、零账号体系，全部数据存本地

## 一、怎么跑起来

```bash
cd D:\workspace\workbuddy\2026-09-14-16-14-42\pet-checkin

npm install     # 首次
npm run dev     # 开发，浏览器打开 http://127.0.0.1:5180

npm run build   # 生产构建 → dist/
npm run preview # 预览生产包

npm run verify  # 一键验证：类型检查 + 78 条冒烟断言 + 生产构建
```

当前开发服务器已在 `http://127.0.0.1:5180` 运行中（手机横屏 / iPhone 视口下效果最佳）。

> **重要**：数据是存在浏览器 localStorage（键名 `pet-checkin-v1`）里的，换浏览器或清缓存 = 换一只宠物。换设备不会同步。

## 三、核心机制落地情况

### 双货币经济
- **食物**：打卡产出 → 投喂 → 饱食度 + 经验 → 进阶（6 阶：幼崽→小兽→灵兽→瑞兽→圣兽→神兽）
- **积分**：只由闯关产出（**无保底**）→ 装饰品 / 现实奖品

### 数值（全部集中在 `src/engine/rules.ts`，改一个数就能调平衡）
| 项 | 值 |
|---|---|
| 每份食物 | +20 饱食度 |
| 每日衰减 | −60（即维持需 3 份/天） |
| 饱食度上限 | 120（≥100 记"顶格"） |
| 日投喂上限 | 6 份（第 6 份 → 当日肥胖） |
| 肥胖双触发 | ① 单日第 6 份 ② 连续 7 天顶格 |
| 消瘦 | 连续 3 天投喂 0 份 |
| 连续打卡奖 | 7 天 +1 份、30 天 +5 份；断签清零 |
| 单任务食物 | 1–3（家长可设，默认 1） |
| 积分 | 答对 ×2 + 星级奖（1/3/5），首通 ×2 |
| 属性 | 每答对 3 题 +1，单关上限 +3；解锁门槛按每关 +3 递进 |
| 血量 / 提示 | 4 + ⌊属性/5⌋ / ⌊属性/10⌋ + 1 |
| 错题复习 | 1 / 3 / 7 / 15 天，连对 3 次出师 |
| 错题注入 | 未掌握错题每次注入 2 道进同类关卡 |
| 一天的分界 | **04:00**（防熬夜赶任务） |

### 数学题库（`src/engine/questions.ts`）
按学而思一年级速算体系程序化生成，12 关递进：
凑十法 → 破十法 → 进位加 → 退位减 → 加减混合 → 连加连减 → 100 以内 → 比大小 → 应用题。
题目用 `QSpec` 序列化存储，可无损还原；错题自动生成 **3 道举一反三变式**。

## 五、冒烟过程中发现并修掉的 7 个真 Bug

| # | 问题 | 修法 |
|---|---|---|
| 1 | `starsOf` 任何及格都 ≥1 星，"0 星不给分"永远触发不了 | 补 50% 阈值，低于 50% 返回 0 星 |
| 2 | 属性成长（+3/关）与关卡解锁门槛（+2→+4→+7→+10）脱节，第 3 关起要求"还差 29 点" | 属性改为每 3 题 +1、上限 +3；门槛改为统一每关 +3 的 `ATTR_LADDER` |
| 3 | 结算页点"下一关"没反应——路由变了但 React 复用了组件实例，上一关答题状态残留 | `App.tsx` 给 `P08Battle` / `P06TaskSubmit` 加 `key` 强制重挂载 |
| 4 | 通关后 Boss 血条还剩一截，观感矛盾 | `finish()` 里 `setBossHp(0)` |
| 5 | 错题集显示"一道错题都没有"，但数量明明是 2（新错题被排到明天复习，`due` 为空） | 新增"排队中（还没到复习日）"分组 + "提前练"按钮 + 还差几天提示 |
| 6 | 成长报告当天全 0（当天要等 04:00 结算才有快照） | 用实时计数器合成 `todayRow` 合并进趋势表 |
| 7 | 从结算页进错题集，返回键回到已结束的答题页 | `nav` 新增 `replace` 动作，替换栈顶而非压栈 |

另外补了两个体验项：favicon（内联 SVG，消除 404）、开发模式下的 `window.__pet` 调试句柄（方便自动化驱动状态）。

## 六、还没做的（两个真阻塞）

### 阻塞 1：深圳 2026 秋语文 / 英语教材目录 ⚠️
语文、英语的 Tab 目前是**置灰的"快来了"**——不是偷懒，是题库必须对准教材目录（识字表、汉语拼音进度、单元词汇），
凭空生成的题目很可能和孩子课堂进度对不上，反而添乱。

需要的材料（任选其一即可开工）：
- 语文：统编版一年级上册 **识字表 + 汉语拼音进度安排**
- 英语：沪教牛津（深圳版）一年级上册 **单元词汇表**

拿到之后，扩建题库 + 错题变式大约是半天工作量，机制层（闯关 / 错题 / 属性）已经完全通用，只差内容。

### 阻塞 2：18 张 AI 美术资源 🎨
山海经主题 6 阶段 × 3 体型 = 18 张。当前用**参数化 SVG**（`src/components/PetAvatar.tsx`）替代：
阶段用体型/角/尾/纹样参数区分，风格统一、零加载、随便缩放不糊。
好处是现在就能跑；代价是细腻度不如插画。出图后替换组件即可，其它代码不用动。

### 待数值策划（不阻塞）
- `EXP_PER_FOOD = 10` 与 `STAGE_EXP` 六阶门槛：现按"3 份/天 × 90 天满阶"倒推，是占位值，需要按期望的养成节奏校准。
- 现实奖品的积分定价（当前样例 800 分兑一次乐园）需要家长按自家激励力度定。

## 七、给家长的两个使用提醒

1. **任务数别少于 3 个**。每日衰减 60 = 维持需 3 份/天，而食物产出 = 任务数 × 食物值。
   任务少于 3 个且食物值都是 1 的话，宠物必然饿瘦。P16 任务管理页顶部有实时**收支提示条**会红字警告。
2. **先去"我的 → 家长"把默认密码 `1234` 改掉**，否则孩子自己就能进家长端发积分。
