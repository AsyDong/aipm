# 线上访问异常排查报告

**日期**：2026-10-13
**对象**：`petkitchen.online` → `124.222.148.45`（腾讯云轻量应用服务器）
**现象**：访问该域名有时报异常，多刷新几次才能进入。

---

## 一、结论（先说结果）

> **这是一次「按域名（TLS SNI）在服务器网络边缘做的概率性连接复位」，
> 高度疑似腾讯云对「未备案域名」的拦截。**
> 与 nginx 配置、服务器性能、本机网络都无关 —— **全球任意客户端表现一致**。

**根治手段只有一条：把 ICP 备案办下来。** 备案通过前，域名访问会持续不稳定（表现为「刷新几次能进」），并可能随时间推移收紧到完全打不开。

---

## 二、怎么定位的（对照实验）

核心手法是**对照组**：同一个服务器 IP，只改变 TLS 握手里的 SNI（域名）以及是否携带 SNI。

| 探测方式 | 结果 |
|---|---|
| 本机直连 IP + `Host` 头（**不带 SNI**） | **200 OK，20/20 全通** |
| 本机 带 `SNI=petkitchen.online` | **约 63 次里仅 3 次成功（≈5%）**，其余 `Connection reset` |
| 本机 带 `SNI=petkitchen.com` | 5/5 全通（该名字没有对应 server 块，落到默认块） |
| 本机 带 `SNI=qq.com` / `taobao.com` | 全通 |
| **国外 8 国节点** 不带 SNI 直连 IP | **8/8 返回 200**（西班牙/法国/伊朗/摩尔多瓦/俄罗斯/瑞典/美国） |
| **国外 10 国节点** 带 `SNI=petkitchen.online` | **10/10 `Connection reset by peer`**（瑞士/法国/印尼/荷兰/俄罗斯/瑞典/乌克兰/美国） |

**读法**：只要 `petkitchen.online` 这个 SNI 出现，握手就在到达 nginx **之前**被复位；不带 SNI 时服务器完全正常。因此复位点在**服务器侧的网络边缘**（对全球生效），既不是 nginx 的问题，也不是本机线路的问题。

---

## 三、为什么「刷新几次能进」

拦截是**概率性放行**（实测约 5% ~ 20% 能通过）。浏览器与用户多次重试，总有一次命中放行 —— 于是表现为「多刷新几次就好了」。这也反过来排除了「前端缓存 / 静态资源 404 / 后端超时」这类常见猜测。

---

## 四、顺带纠正两处旧记录

1. **证书其实是对的**。抓到成功握手时的证书是 `CN=petkitchen.online`，签发者 `TrustAsia DV TLS RSA CA 2024` —— 正是**腾讯云免费 DV 证书**（有效期 2026-09-18 ~ 2026-12-17）。

   之前看到的自签证书 `CN=localhost, O=MyOrg`，是 nginx **默认 server 块的兜底证书**，只在 SNI 不匹配、或客户端不带 SNI 时才会被用到。所以「浏览器报证书错误」这个判断**不成立**。

2. **端口现状**：22（SSH）通、443 通、**80 关闭**、8787 公网关闭（符合 OPS-03 的预期）。

---

## 五、要做什么

### 1）立刻：完成 ICP 备案（唯一根治手段）
- 入口：腾讯云控制台 → 备案 → 使用这台轻量服务器的**备案服务码 / 授权码**发起。
- 备案主体需与域名持有者一致；`.online` 与 `.com` 可分别备案（同一主体可备案多个域名）。
- 备案通过后，通常还需在云侧完成「域名与实例绑定 / 放行」，留意控制台提示。

### 2）备案期间：先用不依赖域名的方式内测
- 前端用「IP + `Host` 头」方式访问（已验证可用）；
- 或把前端临时放到**境外 / 中国香港节点**（无需备案），代价是延迟升高。

### 3）顺手把 80 端口放开
- 80 关闭会挡住：备案核验、Let's Encrypt webroot 校验，以及用户手输域名后的自动跳转。
- 建议开 80 并做 `301 → https`。

### 4）让腾讯云连接器可用（可选，便于我直接上机核查）
- 目前 `lighthouse-ops` 连接器返回 `invalid_token`（未授权）。授权后我可以直接上机看 `nginx -T`、`journalctl -u nginx`、`ss -ltnp`，把配置侧也完整核一遍。

## 六、复现 / 验证命令

```bash
# 不带 SNI（应正常返回证书）
openssl s_client -connect 124.222.148.45:443 </dev/null 2>/dev/null | openssl x509 -noout -subject

# 带正确 SNI（大概率被复位：write:errno=... / 无 ServerHello）
openssl s_client -connect 124.222.148.45:443 -servername petkitchen.online </dev/null 2>&1 | head -3

# 多地节点对照（check-host.net 免费 API，无需 key）
curl -s -H "Accept: application/json" \
  "https://check-host.net/check-http?host=https%3A%2F%2Fpetkitchen.online%2F&max_nodes=10"
# 拿到 request_id 后（约 10 秒再查）：
curl -s -H "Accept: application/json" "https://check-host.net/check-result/<request_id>"
```

> 若腾讯云连接器已授权，也可用远程执行通道直接跑上述检查。
