# 萌宠打卡 App｜需求细化与待确认清单

> 来源：孩子手绘首页原型 + 口述核心玩法
> 版本：v0.1（需求梳理阶段，尚未定稿）
> 日期：2026-09-14

---

## 一、一页纸产品定义

**一句话**：把孩子的日常打卡（习惯养成），翻译成一个"养电子宠物"的成长游戏——家长的打卡任务产出积分，积分喂养萌宠进阶，萌宠陪孩子闯学科关卡。

**目标用户**
- 主要使用者：孩子（学龄期，年龄待确认，见 Q1）
- 管理者/付费决策者：家长

**孩子为什么愿意玩**：宠物会长大、会变强、家园会变好看，努力看得见。
**家长为什么愿意用**：不用催，孩子自己想打卡；顺便练了语数外。

**核心闭环**

```
家长发布每日打卡任务
      ↓
孩子完成 → 家长确认 → 获得积分
      ↓
   ┌──┴────────────┬──────────────┐
   ↓               ↓              ↓
喂养萌宠       宠物商店      带宠物 PK / 学科闯关
（→ 进阶）    （装饰家园）   （语文 / 数学 / 英语）
                                  ↓
                          通关产出经验 + 少量积分 → 回流
```

## 二、角色与端

| 端 | 使用者 | 核心能力 |
|----|--------|---------|
| **孩子端** | 孩子 | 领养蛋 / 孵化、查看今日任务、打卡、喂养宠物、装扮家园、宠物 PK 闯关、商店购买 |
| **家长端** | 家长 | 创建与管理打卡任务、审核打卡、发放积分、设置兑换奖品、查看周报/成长报告 |

> ⚠️ 家长端是**独立App后台**还是**同一App内的家长模式（需密码）**，影响账号体系复杂度，见 Q2。

## 三、模块需求细化

### 3.1 首页（孩子端）

手绘图对应的是 **Day 0 首次进入**的状态：一排功能按钮 + 4 个待孵化的蛋。

**子流程：领养与孵化**
1. 首次进入 → 引导选择一颗蛋（手绘图里是 4 选 1）
2. 点击/互动（摇晃、点几下）→ 破壳动画 → 随机孵出一只小萌宠
3. 给萌宠取名（对应原图"设计名字"）
4. 进入家园首页

**Day 0 之后的首页（稳定态）需要重新设计**，建议至少包含：
- 宠物主视觉 + 当前等级 / 成长进度条
- 今日任务清单入口（带红点：还有几项没完成）
- 积分余额 + 喂养快捷按钮
- 底部/侧边入口：商店、家园、闯关、我的

> 手绘图顶部的一排按钮（设计名字、闯关游戏、宠物PK、兑换奖品、挑选宠物、退出）是扁平平铺的，稳定态建议收敛为**底部 Tab + 1~2 个主行动按钮**，避免低龄孩子选择困难。见 Q3。

---

### 3.2 打卡任务与积分

**家长端：任务管理**
- 创建任务：任务名、图标、分值、执行周期（每天/指定星期）、有效期
- 任务库模板：起床整理、刷牙、练琴 30 分钟、阅读 20 分钟、运动、写作业…
- 每日一键套用昨天 / 复制模板
- 长期任务 vs 临时加分项

**孩子端：打卡**
- 今日任务卡片列表，完成后点击"完成"
- 需要家长复核，还是孩子自己勾？（低龄建议家长复核，见 Q4）

**积分规则**（草案，待确认）
- 完成任务 → +N 分（按任务分值）
- 连续打卡 → 额外连击奖励？（7 天 / 30 天）
- 是否有扣分/失效？（任务过期未完成是否扣分）
- 是否需要每日上限？（防止刷分）

---

### 3.3 宠物养成

**核心问题：宠物进阶的驱动力到底是什么？**

两种玩法，影响经济系统：

| 方案 | 机制 | 特点 |
|------|------|------|
| **A. 积分直兑成长** | 花积分买食物 → 喂养 → 加经验 → 升级 | 简单直接，孩子能立刻感知"我养大了它" |
| **B. 喂养转化双轨** | 打卡得「爱心值」驱动升级；积分用于购买装饰/道具 | 每个孩子都能让宠物长大，不会有"养不起"的挫败感 |

> 我倾向 **B 为主 + A 点缀**：打卡（而非单纯花钱）才是升级主路径，保证产品初心不跑偏。但需要先统一"喂养"到底消耗什么。见 Q5。

**养成维度建议**
- 等级 / 经验（由打卡累计驱动）
- 形态进阶：蛋 → 幼崽 → 少年 → 成年（3~5 阶，视觉明显变化）
- 属性：语文力 / 数学力 / 英语力（由对应学科闯关产出，直接服务于 PK 玩法，形成闭环）
- 心情 / 饱食度：需要定期互动，增加回访（可选，MVP 可砍）

---

### 3.4 宠物商店 & 家园装饰

- **商品类型**：家具、背景、装饰挂件、宠物皮肤/服饰、玩具道具
- **获取方式**：积分购买（主要）、任务解锁（稀有物）、成就奖励
- **家园**：一个可自由摆放的场景，孩子拖动已购装饰进行布置
- **原图里的"兑换奖品"**：建议保留为**独立模块**——虚拟装饰 ≠ 现实奖励。家园装饰用积分，现实奖品（看动画 30 分钟、买一本书）由家长设置并手动核销。见 Q6。

---

### 3.5 宠物 PK / 学科闯关 = 游戏化学习

这是**工程量最大、也最有价值**的模块。

**关卡设计**
- 学科分线：语文（认字、拼音、组词）｜数学（速算、口算）｜英语（单词、拼写）
- 关卡地图：每关 N 道题，答对推进、答错扣血/重试
- 宠物作为"出战角色"：胜负与宠物属性挂钩 → 反向激励日常的打卡与养成

**题库是决定性的**（见 Q7）
- 谁来出题？家长手动录入 vs 内置题库 vs 拍照/教材同步
- 难度如何匹配？按年级？自适应？
- 是否需要语音朗读（低龄孩子不认字）？

**PK 对象**（见 Q8）
- PvE：打系统 NPC / Boss（工程量小，MVP 推荐）
- PvP：和同学/好友对战（需要账号体系、匹配、实时/异步、社交监管，复杂度高）

## 四、数据模型草案

| 实体 | 关键字段 |
|------|---------|
| 孩子档案 | 昵称、年级、头像 |
| 宠物 | 种类、昵称、等级、经验、形态阶段、三科属性值 |
| 任务模板 | 名称、图标、默认分值、周期 |
| 每日任务 | 日期、所属模板、分值、状态（待完成/待确认/已完成/已过期） |
| 打卡记录 | 任务、完成时间、确认人、获得积分 |
| 积分流水 | 变动值、来源（打卡/闯关/消费）、余额、时间 |
| 商品/装饰 | 名称、类型、价格、稀有度 |
| 家园布置 | 已购商品、摆放坐标 |

| 答题记录 | 关卡、正确率、用时、产出属性/积分 |

> 涉及未成年人个人信息，建议：昵称非真名、不开放 UGC 社交、数据本地/加密存储，合规前置。

## 六、MVP 范围建议

**P0（首发必须有）**
首页领养孵化 → 今日任务打卡 → 积分发放 → 喂养 → 宠物 3 阶进阶 → 底部 Tab 导航

**P1（第二版）**
宠物家园 + 商店装饰、学科闯关（先做**数学速算**，题型最标准、最好自动化出）

**P2（后续）**
语文认字/拼音、英语单词、现实奖品兑换审批流、连击/成就系统、PvP

**明确不做（Non-goals）**
- 不做开放式社交/陌生人聊天
- 不做多人实时对战（MVP）
- 不做第三方广告
- 不用宠物"饿死/消失"惩罚孩子（会造成负面体验）

## 七、待确认问题清单

### A. 产品基本盘（最先拍板）

**Q1. 目标孩子的年龄/年级？**
直接决定：是否有大量文字（vs 全图形）、是否需要语音朗读、按钮尺寸、单次游戏时长。
建议：先锁定 1~2 年级，其余年龄段后续扩展。

**Q2. 产品载体是什么？**
微信小程序 / iOS+安卓原生 App / 网页版 / 家里现有平板的一个应用？
（影响技术选型、家长端如何承载、是否需要应用商店上架与儿童隐私审查）

**Q3. 首页导航怎么组织？**
手绘图的 6 个按钮平铺，建议改为"底部 Tab（家园 / 任务 / 闯关）+ 商店 + 我的"，是否认可？

**Q4. 打卡是否需要家长复核？**
a) 孩子自助勾选，家长事后抽查
b) 必须家长确认才发分（更严谨，但增加家长操作成本）
c) 分任务类型：客观任务（拍照/答题）自动，主观任务（练琴）家长点确认

**Q5. 宠物升级到底靠什么？**
a) 消耗积分喂养 → 获得经验（可能"养不起"产生挫败）
b) 打卡产出爱心值 → 喂饱度 → 升级（推荐：努力驱动，非付费感）
c) 两者结合：打卡给食物，食物喂养升级

### B. 经济与奖励

**Q6. "兑换奖品"和"宠物商店"是合还是分？**
建议分开：商店=虚拟装饰即时到账；奖品=现实奖励需家长审批核销。需要现实奖品吗？

**Q7. 积分是否会透支/衰减？**
不打卡会不会扣分？宠物会不会因为不喂养而退化？（建议：不惩罚，只暂停成长）

**Q8. 连击奖励与每日上限？**
是否需要连续 7 天 / 30 天的额外奖励？是否限制每天最多赚多少分（防止刷分）？

### C. 学科闯关（最大工作量模块）

**Q9. 先做哪个学科？**
建议先做**数学速算**（出题可程序化、批改自动、识字量要求低）。

**Q10. 题目从哪来？**
a) 家长手动录入（灵活但家长累）
b) 内置分年级题库（需要一次性内容投入，约几百~几千题）
c) 程序化生成（数学可行，语文/英语不行）
d) 拍照上传教材/错题本

**Q11. 难度怎么定？**
固定按年级？还是答对自动升难度、答错降级（自适应）？

**Q12. PK 打谁？**
a) 系统 NPC / Boss（推荐 MVP）
b) 和认识的同学异步对战（需要好友体系 + 家长同意）
（明确不建议：陌生人匹配）

**Q13. 宠物属性和答题结果如何挂钩？**
是"属性高就有更高血量/更多提示"，还是"纯能力加成"，还是答题本身就直接给属性经验？

### D. 内容与视觉

**Q14. 宠物形象从哪来？**
需要插画设计（或 AI 生成）：1 种宠物 3 阶形态最少要几个？（建议 MVP 先做 3 种宠物 × 3 阶）

**Q15. 一个孩子能养几只宠物？**
单只深养成 vs 多只收集？（收集向会显著增加内容与养成复杂度，MVP 建议单只）

**Q16. 手绘图顶部的"退出"是什么意思？**
退出孩子账号？切换到家长模式？切换孩子？（建议：切换孩子/家长模式需密码，不做退出登录）

### E. 家长端

**Q17. 家长端需要哪些核心功能？**
建议最小集：任务管理、打卡审核、积分调整（手动奖/扣）、奖品审批、一周成长报告。还需要什么？

**Q18. 多个孩子怎么办？**
一个家庭是单孩还是多孩？多孩是否需要各自独立的宠物与积分？
