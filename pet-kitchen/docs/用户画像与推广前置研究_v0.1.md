## 二、诊断结论：为什么这一版只能是「待验证画像假设」

`user-persona.md` §3.2 设了一条硬红线：

> 没有任何一手研究（访谈/问卷/观察）时，**不得输出"最终版画像"**，只能输出"待验证的画像假设"，并明确标注假设清单。

**本项目的实际数据资产盘点**：

| 数据源 | 是否具备 | 说明 |
|---|---|---|
| 深度访谈（家长） | ❌ 无 | 本轮前未做过任何家长访谈 |
| 问卷调研 | ❌ 无 | — |
| 埋点/点击流 | ⚠️ 极少 | 真实用户 ≤10 人，且线上版本落后，数据不具代表性 |
| 真实用户口述 | ⚠️ 1 条 | 《需求细化清单》来源即"**孩子手绘首页原型 + 口述核心玩法**"——这是本项目**唯一的一手用户输入**，且仅覆盖使用者侧 1 人 |
| 家长端反馈 | ❌ 无 | — |

**因此本文件全部画像均为【假设】，每条属性都挂了来源标注；未挂锚点的一律标「待验证」。** 请勿把这份文件当统计结论引用（`user-persona.md` 反模式 8）。

> ⚠️ 另需说明：《需求细化清单》里那一条一手输入来自**你家孩子**，属"最熟悉的极端用户"。它对产品方向极有价值，但**不能代表深圳 1~2 年级家长群体的普遍行为**——这是本轮必须补外部样本的根本原因。

## 三、分群先行：先定「群」，再建「像」

`user-persona.md` §4.1：直接写画像 = 把所有人捏成一个平均人（反模式 1）。正确顺序是先按**行为差异**分群。

### 3.1 分析单元 = 「家庭」，不是「人」

产品本身锁死了这一点：PRD Q15「一个孩子养一只」、Q18「多孩不做」，需求清单 §二明确「孩子端 + 家长端」双角色。所以分析单元是 **1 名孩子 + 1 名家长构成的家庭**——这比单独建孩子画像或家长画像都更贴近真实使用场景（家长的配置行为直接决定孩子的体验）。

> 依据：画像参考 §7 的 B 端红线在此同样适用——**只做"使用者画像"不做"决策者画像"是高频失误**。本项目家长是决策者兼配置者，必须进画像。

### 3.2 分群维度：选了两个「真实导致需求差异」的行为轴

| 维度 | 为什么选它 | 依据 |
|---|---|---|
| **轴 1：孩子对做题的接受度**（愿做 / 抗拒） | 产品自证的核心分叉——PRD §2 风险提示原文：「不闯关 = 零积分 = 商店与现实奖品完全失效。**对"抗拒做题"的孩子等于失去一半激励**」 | 产品设计已预设此差异存在 |
| **轴 2：家长端的操作意愿**（每天陪跑 / 设一次就不管） | 直接决定家长端功能（任务管理/审核/审批）是"必需"还是"负担" | PRD §5.6 家长端最小集 / 需求清单 Q17 |

**刻意不用的维度**：收入、学历、职业——本项目家长端不采集这些字段，且它们不产生产品需求差异（画像参考 §4.2 要求按行为而非人口属性分群）。

### 3.3 分群结果（3 群，符合 C 端 2-4 群上限）

| 优先级 | 群名 | 行为特征（假设） | 为什么是这个优先级 |
|---|---|---|---|
| **P0** | **A 群 · 陪跑型家庭**（孩子做题意愿低 + 家长每天陪跑） | 家长每天发 3~5 个任务并审核；孩子为宠物/家园而打卡，做题需哄 | ① 最贴合产品初心——需求清单 §3.3 明确「打卡（而非单纯花钱）才是升级主路径」；② 是**体验最脆弱**的群（积分唯一产出是闯关，此群天然零积分）；③ 深圳小学家长群中基数大【假设，待问卷验证】 |
| **P1** | **B 群 · 自驱型家庭**（孩子自驱 + 家长低操作） | 家长一次性配好任务模板后极少进家长端；孩子自主答题打 Boss | 体验最顺、口碑传播力最强（他们会主动安利），但**家长端价值感知最弱**，是"用着用着忘了"的流失高危群 |
| **P2** | **C 群 · 学科导向型家庭**（学科提分为主诉求） | 家长盯正确率、错题攻克数、与教材对齐度 | 与产品非目标（PRD §7 Non-goals 无自适应难度、难度固定按年级）契合度最低，且会立刻挑战题库与教材的对齐度——**信任崩塌风险最高** |

## 四、画像卡（五要素 + 数据锚点）

> **化名与部分人口属性为占位**。已按 `user-persona.md` 反模式 2 删除一切与产品无关的虚构细节（星座、宠物、口头禅等一概不写）——细节越"真实"越容易制造虚假确信。
> 【假设】= 未经数据验证的推断；「待验证」= 连假设依据都还不足。

### 4.1 P0 画像 · A 群「陪跑型家庭」

```
【化名身份】阿雅（妈妈，化名），深圳，孩子读 2 年级
【人口属性】
- 地域：深圳（依据：PRD §5.4「语文英语按深圳教材」——这是产品自带的硬约束）
- 孩子年级：1~2 年级（依据：PRD 决策记录 Q1）
- 家长年龄段：30~40 岁区间【假设】
- 设备：手机浏览器（依据：PRD 载体定义「Web 网页版，手机浏览器为主」）
- 收入/学历/职业：不采集、不影响分群（依据：家长端无此字段）【已按反模式 2 删除】
【行为特征】
- 每天晚饭后到睡前是主使用窗口【假设，时间分布待埋点验证】
- 高频动作：发布任务 → 等孩子完成 → 逐条审核 → 处理现实奖品兑换审批（依据：PRD §5.6 家长端最小集）
- 孩子侧：会为「宠物进化」主动打卡，但打开闯关需要家长先哄【假设】
- 关键配置行为：单任务食物值设 1 还是 2、每日任务数设几个（依据：PRD §3.5 收支平衡表，此配置直接决定孩子看到的结果）
【目标动机 · JTBD】
- 家长：「当我忙完一天不想再当监工时，我想要一个孩子自己愿意打开的东西，以便我不用每天催他。」
- 孩子：「当我攒了积分想买家园装饰时，我想要靠打卡就能赚到积分，以便我不用做我不喜欢做的题。」
【核心诉求摘要】
「我要的不是又一个学习软件，是一个**不用我催、孩子自己会打开**的东西。」
```

**痛点场景**（格式：情境 → 行为 → 阻碍 → 情绪）

| # | 情境 | 行为 | 阻碍 | 情绪 |
|---|---|---|---|---|
| **T1** | 孩子打完卡攒了食物，想买家园装饰，打开商店发现**积分是 0** | 反复点商品 → 发现全部买不了 → 转头问妈妈 | **积分唯一产出是学科闯关**（PRD §2 Q19 明确「不要保底」）；此群孩子抗拒做题 → 积分零产出 | 委屈 → 觉得被骗 → 对卡通宠物的信任下降（这句话由 PRD §2 风险提示自证，非我推测） |
| **T2** | 家长只设了 2 个任务（食物值默认 1） | 孩子每天打卡、喂养，但宠物饱食度**每天仍掉 20~40** | 每日衰减固定 60，维持需 3 份/天（PRD §3.2 / §3.5）。PRD 已预判并建议"把单任务食物值调到 2"，**但这是需要家长主动读文档才知道的** | 孩子："宠物怎么越来越饿" → 家长被埋怨 → 觉得"这软件没用" |
| **T3** | 孩子连续打卡 20 天后，生病断了一天 | 第二天打开发现**连击归零** | PRD Q20 拍板「断签连续天数清零」 | 孩子崩溃 → 家长怀疑产品"太狠" → 直接卸载 |

> **注意 T2/T3 是产品**设计决策**带来的可用性风险，不是 bug。** 两者的共同点是：**产品把"正确配置"和"容错"的责任推给了家长**，而家长不会去读 PRD。这属于研究结论可直接推动的设计议题（见 §八）。

## 五、待验证假设清单（每条含验证方式 + 通过阈值）

> 按 `user-persona.md` §5.1 与 agent.md 第五条 5.4，所有假设登记于此，供回访核对。

| # | 假设内容 | 验证方式 | 通过阈值 |
|---|---|---|---|
| **H1** | A 群（陪跑型）占社群家长的大多数，≥50% | 家长问卷单题分群 + 现有 10 家庭对照 | ≥50% 落入 A 群则维持 P0 |
| **H2** | 「积分只能靠闯关」确实造成 A 群孩子的可感知挫败 | 家长访谈追问「孩子有没有买不了东西的时候」+ 观察孩子现场反应 | ≥3/5 家长能复述出该场景则成立 |
| **H3** | 家长端"需密码进入"是打开频率的第一抑制因素 | 家长访谈（问上次打开时间及原因）+ 未来埋点 | 若 >50% 家长一周内未打开，则需改设计 |
| **H4** | 孩子主使用时段集中在 18:00–21:00 | 埋点时段分布 | 该窗口占比 ≥60% 则成立 |
| **H5** | 家长一次配置后基本不再改任务（配置粘性高） | 埋点 + 访谈 | 首周后再编辑率 <20% 则成立 |
| **H6** | 语文/英语题库与深圳在用教材版本**尚未完全对齐** | 请 2 位家长提供课本目录逐一比对 | 存在对不上则必须优先修，否则 C 群不可推广 |
| **H7** | 群内负面口碑（教材不对版）的传播速度快于正面口碑 | 访谈 + 社群观察 | 定性观察即可，不设阈值 |

## 六、北极星指标校验（GSM）

沿用《需求细化清单》§八的建议值「**周活跃打卡天数**」，按 `metrics-analytics.md` §1.3 五问校验：

| # | 校验问 | 结论 |
|---|---|---|
| 1 | 反映用户真的得到核心价值？ | ✅ 是——打卡就是产品初心（需求清单 §3.3） |
| 2 | 可被准确及时测量？ | ✅ 是——PRD §6 数据模型已有「每日任务」「每日快照」表 |
| 3 | 团队能通过行动影响它？ | ✅ 是——任务模板、连击奖励、家长端提示均可作用 |
| 4 | 它涨了长期价值是否涨？ | ⚠️ **需改写**——本项目业务目标为「社群福利（免费）」，无直接营收。应改写为"社群留存价值"：打卡天数涨 → 家长对工具的依赖涨 → 社群黏性涨。**此因果链为【假设】** |
| 5 | 一句话能懂？ | ✅ 是 |

**GSM 表**（Goal → Signal → Metric）

| Goal | Signal | Metric（口径） |
|---|---|---|
| 社群成员家庭把它变成日常习惯 | 同一家庭连续 ≥5 天出现打卡行为；家长端周报被打开 | 周活跃打卡天数（**按家庭统计，取中位数而非均值**——家庭间差异大，属长尾分布，见 `metrics-analytics.md` §4.1） |
| 家长相信它有价值 | 家长主动打开周报、并对奖品做审批 | 家长端周报打开率 = 周内打开周报的家庭 ÷ 当周有活跃打卡的家庭 |
| 孩子愿意持续玩 | 一周后仍在闯关 | D7 家庭留存率 = 第 7 天仍活跃家庭 ÷ 第 0 天新增家庭 |

**护栏指标**（`metrics-analytics.md` §5.3：主指标外必须监控反指标）

| 护栏 | 为什么必须盯 |
|---|---|
| 单次使用时长 | 产品有防沉迷设计（PRD §7，单次限时 15 分钟）——**使用时长涨可能是坏事** |
| 孩子作答正确率 | 若 <60%，说明难度过高【经验参考值，非行业基准】→ 会直接引发挫败与流失 |
| 家长端任务编辑频次 | 频繁编辑说明任务模板不好用，而非家长勤快 |

## 七、下一步推广：我能承接的部分 + 三条硬约束

### 7.1 结论先行

**推荐路径：先私域（自有家长微信群）小范围跑通，公域（小红书/抖音）推到「备案完成 + 重部署 + 教材对齐」三项之后。**

**理由（研究视角，非投放视角）**：
1. 人群高度**同质且密集**——深圳 + 1~2 年级 + 已在你群里，触达成本≈0，反馈回路最短；
2. 真实用户仅 ≤10 人，**样本量不足以支撑任何公开获客**——现在放量只会把问题一次性暴露给陌生家长，且不可回收；
3. 家长群的**口碑可追踪**（你能看到谁在说、说什么），公开平台的负面你既看不见也回不了。

### 7.2 触达可行性分档（含合规约束）

| 渠道 | 你现在有 | 可行性 | 硬约束 |
|---|---|---|---|
| **自有家长微信群** | ✅ | ✅ **可立即用** | 《上线清单》4.2 明确：网站**纯免费、无任何商业化入口**时，"社群里私下告知网址"是**合规最安全**的路径 |
| **小红书 / 抖音等公开平台** | ✅ | ⚠️ **须满足三个前提才安全** | 见下 |

**公开平台的三个前提（缺一不可）**：
1. **备案已完成**——否则点进来 ≈95% 打不开（《上线清单》零节）；
2. **公开内容里不出现**「加入社群 / 扫码进群 / 咨询我们 / 联系我们」**任何入口**——《上线清单》4.2 判定此为 ⚠️ 中高风险，且是**个人备案的明确禁区**；
3. **网站内不出现**价格表、购买按钮、打赏码、广告位——《上线清单》4.2 判定为 ❌ 经营性，回到 4.1 的无证经营区间。

> ⚠️ **必须提示的冲突**：你的业务目标是"社群福利（免费给家长社群用）"，而《上线清单》4.2 的可行结构**建立在"社群与咨询走线下、网站与社群在公开渠道不互相引流"之上**。一旦在小红书/抖音上出现引流社群的动作，结构就从 ✅ 滑向 ⚠️——这**不是文案问题，是备案能否保住的问题**。
>
> 若想公开推广，安全写法是：公开内容**只讲方法/场景/工具本身**（"深圳一年级家长怎么让孩子自己打卡"），网址以自然提及方式出现，**全程不出现社群与咨询**。

**另需向腾讯云备案客服确认一处口径冲突**：本人此前记录称"备案期间域名不得解析访问"，而《上线清单》4.1 称"备案核验要求网站可正常访问、且内容与填报一致"——两者表述不一，各省与接入商要求可能不同，**建议提交前明确问一次**。

### 7.3 沟通信息方向（说什么）——来自 JTBD 动机

| 群 | 说什么（基于其 JTBD） | **不要说什么** |
|---|---|---|
| A 群（P0） | "孩子**自己会打开**"、"不用催" | 不提"提分""成绩"——既不准确（无数据支撑），也踩备案敏感词 |
| B 群 | "一周看一眼就知道孩子做了什么"（把家长端周报推成主角） | 不要强调"需要每天操作"，此群最怕麻烦 |
| C 群 | **暂不建议面向此群推广**——待 H6（教材对齐）验证通过后再说 | 不要用"专业""权威""提分" |

> **通用红线**：任何渠道的文案都**不要出现**「在线教育」「培训」「专业指导」「诊断」等词——《上线清单》4.1 明确可能被要求补前置审批。

### 7.4 明确不由我承接

投放预算与渠道采买、内容选题与排期、达人合作、裂变/分销活动设计、投放素材产出、SEO/ASO。

## 八、最小验证计划（S2 调研方案）

按 `user-persona.md` §8 Step 3「每类 5-8 人深访」是标准配置，但**本项目真实用户仅 ≤10 人，硬套会做不出来**。据实际规模降级为：

| 动作 | 样本 | 产出 | 优先级 |
|---|---|---|---|
| **A. 家长快访** | 5 人（A 群 3 + B 群 2，从自有群内选） | 验证 H1/H2/H3/H4 | **P0** |
| **B. 教材目录比对** | 2 位家长提供 1~2 年级语文/英语课本目录 | 验证 H6，**决定 C 群能否推广** | **P0** |
| **C. 现有数据回验** | 现有 ≤10 家庭的后台记录 | 验证 H4/H5（时段分布、编辑率） | P1 |
| **D. 家长问卷** | 群内 ≥30 份（**非** 384 份——群体规模本身有上限，采全员普查口径） | 验证 H1 分群占比 | P1 |

> 说明：`survey-design.md` 的标准样本量 n≈384（95% 置信、5% 误差）适用于**推断总体比例**。本项目服务对象就是自有社群、规模有上限，属**普查而非抽样**，因此不适用该公式——这是有意识的偏离，不是疏漏。

**可直接推动的设计议题（研究结论的延伸，供后续排期）**：
- T1 → 是否会为"抗拒做题"的孩子开辟**非做题的积分来源**（PRD D3 曾拍板走"家长发布打野任务"，需确认是否已落地）
- T2 → 家长端**任务数 < 3 时主动提示**食物收支，而非只写在文档里（PRD §3.5 已要求 P16 显示，需确认实现）
- T3 → 断签清零是否提供**宽限/补签**机制
