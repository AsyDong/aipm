# 后端接入说明（P0 接口层）

> 对应决策：先抽接口层，部署目标 = 一台轻量服务器。
> 本文描述的是**当前已完成的部分**：契约层已就位，正式后端（P1）尚未开发。

## 一、现在是什么状态

前端已经把「出题」和「批改」从页面里彻底抽出来了。页面只认契约，不认具体实现。

```
页面 (P08Battle / P10WrongBook)
        │  只调这 3 个函数
        ▼
  provider/index.ts  ── 路由 + 降级 ──┬── local.ts   同步、零成本、零网络
                                      └── remote.ts  HTTP → 你的轻量服务器
```

- **默认跑 local**，行为和抽取之前完全一致：程序化生成、答案 100% 确定、零延迟。
- **配了 `VITE_API_BASE_URL` 才走 remote**，连不上会自动回落 local，孩子那边不会玩不了。

## 二、页面侧只依赖三个函数

| 函数 | 作用 | 返回 |
|---|---|---|
| `generateQuestions(req)` | 出本关题目 | 本地同步返回，远端返回 Promise |
| `generateVariants(seed, n)` | 举一反三变式 | 同上 |
| `gradeAnswer(q, input)` | 判分 | 答案唯一的题同步返回，开放题异步 |

`MaybeAsync<T>` 是刻意的：本地实现在渲染期就把题出好，**不闪 loading**；远端实现才给 loading 态。这个差别由 `isThenable()` 判定。

## 三、接口契约（后端要实现这三个）

```
POST /api/gen      请求 { subject, levelId, count, inject?, attr? }  响应 { questions[], source, degraded? }
POST /api/variants 请求 { seed: Question, count }                    响应 { questions[], source }
POST /api/grade    请求 { question: Question, input }                响应 { correct, by, feedback?, deferred? }
```

**`source` 字段很关键**，它驱动成本控制：

| source | 含义 | 成本 |
|---|---|---|
| `cache` | 命中题库 | 零 |
| `llm` | 模型新生成 | 有 |
| `local` | 本地生成（前端兜底） | 零 |

前端会累计这些调用（见 `providerStats()`），命中率低于 85% 就该查后端是不是没做缓存。

**`inject` 传的是 `QSpec` 而不是题面** —— 服务端拿到 `{ kind, a, b, op }` 就能无损重建原题，也能从同一份 spec 派生变式。这个设计前端已经用了，后端直接接。

## 四、判分：本地优先是成本闸门

```
gradeAnswer()
   ├─ 答案唯一（数学速算）→ gradeLocally()  本地精确比对，零成本，永远不走网络
   └─ 开放答案（看图说话/造句/手写）→ 远端模型批改
```

**不要动这条规则**。大模型会算错 7+8，本地判分器不会。接后端之后，本地判分器不是被替换，而是升级成"最便宜的那道判分关"——正式后端里也应该先跑它（见 `tools/mock-api.ts` 的 `/api/grade` 实现）。

`gradeLocally` 已做输入归一化：全角数字转半角、去空格、去前导 0、长度上限 4 位、非数字判错。

## 五、降级与可观测

- 远端失败/超时 → 自动回落本地，`degraded: true`，页面顶部显示「连不上服务器，已用本地题目」。
- 所有调用计数在 `providerStats()`：远端成功次数、本地次数、降级次数、最后一次错误。开发期控制台可查 `__provider.stats()`。
- 开放题在断网时返回 `deferred: true`，页面把题放回队尾重做，**不算孩子错**。

## 七、部署到轻量服务器的两个注意点

**1. CORS —— 已经踩过一次**

开发时页面在 5180、服务在 8787，属跨源，浏览器直接拦。本次实测就是卡在这里（`Failed to fetch` → 走了降级）。

- 临时方案：后端加 `Access-Control-Allow-Origin` 响应头 + 处理 `OPTIONS` 预检（参见 `tools/mock-api.ts`）。
- **推荐方案：nginx 把 `/api` 反代到同域**，前端 `VITE_API_BASE_URL` 留空或填同域地址，彻底避开 CORS，也少一次预检往返。

**2. 密钥只在服务端**

`VITE_` 前缀的变量会被打进前端 bundle，任何人 F12 都能看到。**后端地址可以放 `VITE_`，模型密钥绝对不行** —— 密钥只写进服务器环境变量。

# v1.1 部署实录（2026-09-15）

**P1 已落地**：CloudBase PostgreSQL + 轻量服务器（Ubuntu 22.04，公网 `124.222.148.45`）。

## 架构现状

```
浏览器(前端) ──HTTP──▶ 轻量服务器:8787 (Docker node:22-alpine, /opt/pet-checkin/server.cjs)
                          │ Bearer API Key（只存服务器环境变量）
                          ▼
                      CloudBase PG (base-d1g1prwb6d0165455, exec-pgsql 参数化 SQL)
```

## 数据库（CloudBase PG，迁移版本 20260915104000）

14 张表：`children / pets / task_templates / daily_tasks / ledgers / level_records /
questions / attempts / wrong_items / daily_snapshots / prizes / redeems / llm_calls / sync_state`。

- 迁移文件：`cloudbase/migrations/20260915104000_create_pet_checkin_tables.sql`
- `attempts` / `ledgers` 以 `op_id` 唯一约束做**幂等**——客户端重试不会写重
- `daily_snapshots` / `level_records` / `wrong_items` 以业务键 upsert（后到覆盖）
- `questions.verified=false` 的题不会下发（大模型生成题的安全闸门）
- 保留字教训：`full` 是 PG 保留字，快照表列名用 `is_full`（API 层映射回 `full`）

## 后端服务（server/server.ts，零依赖）

- 打包：`npx esbuild server/server.ts --bundle --platform=node --format=cjs --outfile=server/server.build.cjs`（23KB）
- 接口：`GET /health`、`POST /api/gen|/api/variants|/api/grade`（复用前端同款引擎）、
  `POST /api/sync`（op 幂等入库）、`GET /api/report`（快照 + 薄弱考点）
- 部署：代码经 CloudBase 存储中转上传 → 服务器 `/opt/pet-checkin/server.cjs`
  → `docker run -d --name pet-checkin --restart always --env-file /opt/pet-checkin/env/pet-checkin.env
  -p 8787:8787 -v /opt/pet-checkin/server.cjs:/app/server.cjs:ro node:22-alpine`
- 防火墙已放行 TCP 8787；实测公网 `/health`、`/api/gen` 均通
