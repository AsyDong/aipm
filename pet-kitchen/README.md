# 萌宠打卡 · pet-kitchen

> 面向**深圳 1–2 年级**孩子的「打卡养宠 + 闯关练题」Web 应用。
> 家长发布打卡任务 → 孩子完成后得**食物** → 投喂山海经萌宠、逐步进阶；
> 闯关答题得**积分** → 买装饰 / 兑换现实奖品，答错的题进错题集自动回炉。

- **技术栈**：Vite 5 + React 18 + TypeScript(strict) + Tailwind CSS 3 + zustand(persist)
- **前端**：18 个页面，纯静态，可离线运行
- **后端**：Node 22 零依赖单文件服务（复用前端同一套出题/判分引擎）
- **数据库**：腾讯云 CloudBase PostgreSQL（14 张表）

> 📁 **目录名说明**：仓库约定目录名为 `pet-kitchen`，应用内部标识（localStorage 键、包名、容器名、日志前缀）仍为 `pet-checkin`，两者并存不影响运行。

## 一、架构总览

```
                        ┌──────────────────────────────────────────┐
   孩子 / 家长           │  前端 SPA（React + Vite）                 │
        │               │  ├─ localStorage  宠物/任务/积分/错题     │
        │               │  └─ IndexedDB     打卡照片·录音（30天清理）│
        └──────────────▶│                                          │
                        │  provider/index.ts  ← 出题·判分的唯一入口  │
                        └───────────┬──────────────────────────────┘
                                    │ ① 未配 VITE_API_BASE_URL：纯本地
                                    │ ② 配了地址：HTTP 调后端，失败自动降级
                                    ▼
                        ┌──────────────────────────────────────────┐
                        │  后端服务 server/server.ts（零依赖）      │
                        │  轻量服务器 :8787（Docker, restart=always）│
                        │  ├─ /api/gen  /api/variants  /api/grade   │
                        │  └─ /api/sync /api/report                 │
                        └───────────┬──────────────────────────────┘
                                    │ Bearer API Key（仅存服务器环境变量）
                                    ▼
                        ┌──────────────────────────────────────────┐
                        │  CloudBase PostgreSQL（exec-pgsql）       │
                        │  14 张表：题库 / 答题流水 / 账本 / 快照…  │
                        └──────────────────────────────────────────┘
```

**两条独立的降级链路**（这是设计的核心，别绕过去）：

1. **出题降级**：后端不可用 → 自动回落本地程序化生成，孩子照常玩，界面提示「连不上服务器，已用本地题目」。
2. **判分降级**：答案唯一的题（数学速算）**永远本地判**，零网络请求；只有开放答案的题才需要走模型。

## 三、快速开始

### 前端

```bash
npm install
npm run dev       # http://127.0.0.1:5180
```

不配任何环境变量即可完整游玩（纯本地模式，零网络、零成本）。

### 一键验证

```bash
npm run verify    # 类型检查 → 79 条冒烟断言 → 生产构建
```

改了任何数值规则后跑一遍，就知道有没有跑偏。

### 本地验证前后端契约

```bash
npm run mock-api            # 起一个复用真实引擎的 mock 服务，端口 8787
# 另开终端：把 .env 里的 VITE_API_BASE_URL 指向 http://127.0.0.1:8787
```

### 后端 + 数据库

```bash
npx esbuild server/server.ts --bundle --platform=node --format=cjs \
  --outfile=server/server.build.cjs          # 产物约 23KB，零依赖

PORT=8787 \
TCB_ENV_ID=<你的 CloudBase 环境 ID> \
TCB_API_KEY=<CloudBase API Key> \
SYNC_TOKEN=<自建访问令牌> \
node server/server.build.cjs
```

数据库建表、服务器部署、防火墙、排错，见 **[部署说明.md](./部署说明.md)**。

## 五、核心数值规则

全部集中在 `src/engine/rules.ts`：

| 项 | 值 |
|---|---|
| 每份食物 | +20 饱食度、+10 经验 |
| 每日衰减 | −60（即维持需 **3 份/天**） |
| 饱食度上限 | 120（≥100 记"顶格"） |
| 日投喂上限 | 6 份（第 6 份 → 当日肥胖） |
| 肥胖双触发 | ① 单日第 6 份 ② 连续 7 天顶格 |
| 消瘦 | 连续 3 天投喂 0 份 |
| 连续打卡奖 | 7 天 +1 份、30 天 +5 份；断签清零 |
| 单任务食物 | 1–3（家长可设，默认 1） |
| 积分 | 答对 ×2 + 星级奖（1/3/5），首通 ×2，**无保底** |
| 属性 | 每答对 3 题 +1，单关上限 +3；解锁门槛每关 +3 |
| 血量 / 提示 | 4 + ⌊属性/5⌋ / ⌊属性/10⌋ + 1 |
| 错题复习 | 1 / 3 / 7 / 15 天，连对 3 次出师 |
| 错题注入 | 未掌握错题每次注入 2 道进同类关卡 |
| 一天的分界 | **04:00**（防熬夜赶任务） |

### 答题规则：写对为止

答错或跳过**不公布答案**，题目回到队尾稍后重做，**队列清空（每道题都真正做对）才算过关**。
星级只按「**第一次就答对**」的题数算，重做不会刷分。

## 六、关键设计决策

| 决策 | 理由 |
|---|---|
| **判分本地优先** | 大模型会算错 7+8，本地 `calc(spec)` 100% 正确且零成本。本地判分器是「最便宜的那道判分关」，不是要被替换的旧代码。 |
| **题目用 `QSpec` 序列化** | 存的是 `{kind,a,b,op}` 而非题面 → 可无损重建、可派生变式、可脱离大模型独立存在，也方便入库和跨端同步。 |
| **契约层用 `MaybeAsync<T>`** | 本地实现同步返回 → 渲染期就出好题，**不闪 loading**；远端才给加载态。 |
| **流水用 `op_id` 幂等** | 孩子那边网络不稳定，客户端重试不能把积分刷两遍。 |
| **`questions.verified` 安全闸门** | 大模型生成的题默认 `verified=false`，审核通过才下发。 |
| **用户数据先留本地** | 照片/录音属儿童敏感个人信息，不采集就不担责。题库是共享资产可以先上云。 |

## 九、安全须知

- ⚠️ **`VITE_` 前缀的环境变量会被打进前端 bundle**，F12 可见。后端地址可以放，**模型密钥绝对不行** —— 只写服务器环境变量。
- ⚠️ 家长端默认密码 `1234` **必须先改掉**，否则孩子自己就能进家长端发积分。
- ⚠️ `TCB_API_KEY` 是库级管理员权限，等同数据库密码：只放服务器 `/opt/pet-checkin/env/pet-checkin.env`，不进 git、不进前端。
- ⚠️ 接大模型后，孩子看到的所有模型输出都必须过一遍内容安全审核。
