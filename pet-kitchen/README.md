# 萌宠打卡 · pet-kitchen

> 面向**深圳 1–2 年级**孩子的「打卡养宠 + 闯关练题」Web 应用。
> 家长发布打卡任务 → 孩子完成后得**食物** → 投喂山海经萌宠、逐步进阶；
> 闯关答题得**积分** → 买装饰 / 兑换现实奖品，答错的题进错题集自动回炉。

- **技术栈**：Vite 5 + React 18 + TypeScript(strict) + Tailwind CSS 3 + zustand(persist)
- **前端**：26 个页面/视图，纯静态，可离线运行
- **后端**：Node 22 零依赖单文件服务（复用前端同一套出题/判分引擎）
- **数据库**：腾讯云 CloudBase PostgreSQL（14 张表）

> 📁 **目录名说明**：仓库约定目录名为 `pet-kitchen`，应用内部标识（localStorage 键、包名、容器名、日志前缀）仍为 `pet-checkin`，两者并存不影响运行。

> 📌 **进度与任务追踪**：唯一条目在 **[docs/任务看板.md](./docs/任务看板.md)** —— 已完成 / 进行中 / 阻塞 / 待决策全在那张表里，
> 本 README 只描述"已成型的能力"，不再维护进度。

                        └────────────────────┘  └──────────────────────┘

**三条独立的降级链路**（这是设计的核心，别绕过去）：

1. **出题降级**：后端不可用 → 自动回落本地程序化生成，孩子照常玩，界面提示「连不上服务器，已用本地题目」。
2. **判分降级**：答案唯一的题（数学速算 / 认读选择题）**永远本地判**，零网络请求；只有开放答案的题才需要走模型。
3. **跟读降级**：评分服务不可用时，跟读关顶部显示一条「⚠ 连不上评分服务」，其它四个版块完全不受影响。

## 三、快速开始

### 前端

前置：Node 18+（推荐 22，后端容器用 node:22-alpine）。

```bash
npm install
npm run dev       # http://localhost:5173（vite.config.ts 中配置）
```

不配任何环境变量即可完整游玩（纯本地模式，零网络、零成本）。
唯一例外是英语的「跟读评分」关：它需要后端 + 讯飞密钥，没配会显示提示条，不影响其它四个版块。

### 一键验证

```bash
npm run verify    # 类型检查 → 364 条冒烟断言 → 生产构建
```

改了任何数值规则后跑一遍，就知道有没有跑偏。

### 拼音发音资源

拼音版块用的是**真人发音 mp3**（843 条，8.1 MB），已随仓库放在 `public/audio-py/`，
由 `src/pinyin/audio-manifest.json` 建立"音节 → 文件"映射，`vite` 构建时自动进 `dist/`。
新增音节时按 `shengmu/ yunmu/ zhengti/ pindu/` 四类放文件并同步 manifest 即可，无需改代码。

### 本地验证前后端契约

```bash
npm run mock-api            # 起一个复用真实引擎的 mock 服务，端口 8787
# 另开终端：把 .env 里的 VITE_API_BASE_URL 指向 http://127.0.0.1:8787
```

### 后端 + 数据库

```bash
npx esbuild server/server.ts --bundle --platform=node --format=cjs \
  --outfile=server/server.build.cjs          # 产物约 120KB，零依赖

PORT=8787 \
TCB_ENV_ID=<你的 CloudBase 环境 ID> \
TCB_API_KEY=<CloudBase API Key> \
SYNC_TOKEN=<自建访问令牌> \
XFYUN_APP_ID=<讯飞 APPID> \
XFYUN_API_KEY=<讯飞 APIKey> \
XFYUN_API_SECRET=<讯飞 APISecret> \
node server/server.build.cjs
```

数据库建表、服务器部署、防火墙、排错，见 **[部署说明.md](./部署说明.md)**。

## 四、闯关：五个版块

「闯关」进去先看到**版块中心**（5 张卡片），选一个版块才进关卡地图。
其中**拼音**与**英语**是多游戏中心（宫格入口），数学 / 识字 / 综合是关卡列表：

| 版块 | 内容 | 玩法 | 关卡数 |
|---|---|---|---|
| 🅰️ **拼音** | 拼音方块世界：字母表 / 学习讲堂 / 拼读演示 / 听力挑战 / 识字挑战 / 拼装工坊 / 发音擂台 / 21 天计划 | 内置页面（`src/pinyin/`） | 15 关 + 9 个单元测试 |
| 🔢 **数学** | 速算 10 以内 → 100 以内、连加连减 | 选择题闯关（P08） | 12（含 2 个 Boss） |
| 🔤 **英语** | **课本**（跟读评分 + 认读巩固 + 听音选词）/ **牛津树**（剑桥预备级电子闪卡） | 录音评分（P18）+ 选择题（P08） | 37（课本 27 + 牛津树 10） |
| 📖 **识字** | 已学音拼读、看字标音、古诗对句 | 选择题闯关（P08） | 8（含 1 个 Boss） |
| 🎲 **综合** | 混合大乱斗（四路随机抽题）+ 错题复习（整关由错题拼成） | 选择题闯关（P08） | 2 |

几点约定：

- **版块内 `index` 必须连续且唯一** —— Boss 解锁（往前数 5 关）和结算页的「下一关」都按它找。
- **拼音版块已整体搬进本应用**：不再是 iframe 子应用，数据与玩法都在 `src/pinyin/`，页面是 P20–P26。
  早年 `src/engine/questions.ts` 里的 `PINYIN_LEVELS`（c1…c20）是**历史存档**，地图里看不到，
  但定义必须留着 —— 老存档的 `level_records` 与错题本还挂着这些 id，`levelById()` 仍要能解析。
- **拼音的结算完全走主应用**：闯关涨「语文」属性、错题进统一错题本（`spec.kind` 用 `pyw_*` 以便回放）、
  积分与星级走 `useStore.finishBattle` —— 只有一个钱包，孩子不会面对两套货币。
- **英语分两条线**（P07 里的二级分栏）：`track='textbook'`（课本）/ `track='oxford'`（牛津树）。
  牛津树就是原来的「闪卡速记」那批剑桥预备级闪卡，**内容与玩法完全没改**，只是从"任务专用、不进地图"改成挂进英语版块能被找到。
- **综合关的属性**：它没有自己的属性。解锁门槛和血量按**三科均值**算（`attrOf`），成长则**轮转摊到三科**（`gainAttrs`）——
  一关只加一份，不会变成"三科各加一份"的刷属性漏洞。
- **综合关的错题归科**：每道题按自己的 `kind` 归科（`subjectOfKind`），不会被一股脑塞进"综合"。

## 五、英语跟读评分（课本）

链路：浏览器录音 → 重采样 16kHz 单声道 WAV → `POST /api/score` → 讯飞 ISE → 逐词分数。

**为什么这么绕**：讯飞官方明确写「不支持跨域，请在后端调用」。`APIKey/APISecret` 放进前端等于送人刷额度，
所以密钥只在服务端（环境变量 `XFYUN_*` 或 `server/xfyun.config.json`，模板见 `server/xfyun.config.json.example`）。

### 关卡组织

6 个单元 × 3 档 = 18 关，**一步一步来**：单词关先求音准 → 短语关求连读 → 句子关再求流利。
关卡 id 约定 `rd-<unit>-<档位>`（`w`/`p`/`s`），`play:'read'`，路由到 P18，不进 P08。
一个单元的单词有 20 多个，一关只练一批（词 10 / 短语 6 / 句 6），下一批按 `playCount` 轮转，多玩几次自然轮完。

### 对齐与星级（`src/engine/follow.ts`，纯函数可单测）

- **增读词**（`dp_message=32`）先剔除，不参与评分；
- 命中即从待匹配池里删除，先试同下标、再全局按词形找；
- **漏读**看 `dp_message==16`（带 0 分而非空值）；
- **星级"短板压顶"**：3 星要求总分 ≥85 **且**每个词都 ≥85 **且**无漏读 —— 一个词含糊过去也拿不到 3 星。
- 音质/内容异常码（28673 没声音、28676 读的内容对不上、28680 环境吵…）都翻成给孩子看的中文提示。

### 自查

```bash
curl -s http://127.0.0.1:8787/api/score/health
# credentials_ready=true 才算配好；source 会告诉你密钥是从 env 还是 json 读到的
```

## 六、拼音方块世界（P20–P26）

原来的独立 Vue 应用 `pinyin-world` 已**整体移植**进本应用（`src/pinyin/`），视觉统一到 pet-kitchen 的淡蓝风格。

| 页面 | 内容 |
|---|---|
| P20 | 拼音版块主页：今日任务卡 + 成长区 / 游戏区 / 学习区三组宫格 |
| P21 | 拼音字母表：点方块听真人发音，读过的变绿（63 个音） |
| P22 | 学习讲堂：九课拼音规则，标签可点读 |
| P23 | 拼读演示：选声母 + 韵母 + 声调，拼出音节并朗读 |
| P24 | 通用游戏页（按参数分发）：听力挑战 / 识字挑战 / 拼装工坊 / 发音擂台 / 关卡 / 单元测试 |
| P25 | 闯关地图：15 关 + 9 个单元测试，星级走主应用 `levels` |
| P26 | 21 天打卡计划：今日任务 / 复习安排 / 进度回顾 |

**移植时的三处关键决定**：

- **奖励全融入主应用**：拼音原本自带绿宝石 / 徽章墙 / 独立错题本，现在统一走 pet-kitchen 的积分、星级与错题本，

- **题目转成主应用 `Question`**（`toApp.ts`）：拼音题也能进统一错题本，享受遗忘曲线和跨科复习。
- **发音仍是真人 mp3**：原应用 843 条录音一条没丢，只把路径改成 `public/audio-py/` 并由 manifest 映射。

## 八、核心数值规则

全部集中在 `src/engine/rules.ts`：

## 九、关键设计决策

| 决策 | 理由 |
|---|---|
| **判分本地优先** | 大模型会算错 7+8，本地 `calc(spec)` 100% 正确且零成本。本地判分器是「最便宜的那道判分关」，不是要被替换的旧代码。 |
| **题目用 `QSpec` 序列化** | 存的是 `{kind,a,b,op}` 而非题面 → 可无损重建、可派生变式、可脱离大模型独立存在，也方便入库和跨端同步。 |
| **契约层用 `MaybeAsync<T>`** | 本地实现同步返回 → 渲染期就出好题，**不闪 loading**；远端才给加载态。 |
| **流水用 `op_id` 幂等** | 孩子那边网络不稳定，客户端重试不能把积分刷两遍。 |
| **`questions.verified` 安全闸门** | 大模型生成的题默认 `verified=false`，审核通过才下发。 |
| **用户数据先留本地** | 照片/录音属儿童敏感个人信息，不采集就不担责。题库是共享资产可以先上云。 |
| **拼音放弃 iframe，改成内置页面** | 初版用 iframe 套 `pinyin-world` 构建产物，虽然有 8.3 MB 进仓库、两套状态各记各的、样式与主应用割裂三个问题。改成把数据/引擎/页面整体移植为 React（`src/pinyin/`），奖励走统一钱包、发音仍是那 843 条真人 mp3 —— 代价是一次性移植，收益是此后只有一个应用。 |
| **讯飞走服务端转发** | 官方明确「不支持跨域」，且密钥进前端等于送人刷额度。前端只发 base64 WAV，签名与连接全在 `server/xfyun.ts`。 |
| **跟读评分保持零依赖** | 用 Node 22 内置的全局 `WebSocket`（undici）+ `node:crypto`，服务端依旧零 npm 依赖，部署包仍是单文件。 |
