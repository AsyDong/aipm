    # English Adventure
    
    An English-only listening adventure for beginners. The long-term learning goal is 500 listening words; this is not a claim that the current preview teaches or assesses those words.
    
    Phase 3.2 turns it into a small game world: a Fruit Island map with one level per unit, a monkey guide who talks in short English lines, a market scene where fruit drops onto a counter, and stars kept on the map (this device only). Listen & Find is the first level type: five listening rounds, randomized picture choices, replay, hints, friendly retries, pause/resume, stars and a session summary. The default collection is Power Up 0, Unit 3, printed page 28: apple, banana, grapes, orange and watermelon. An explicitly independent woodland sampler demonstrates content and scene reuse.
    
    Phase 4 adds Listen & Say in Talking Market: listen, tap Record, say the word and tap Done (capture stops automatically after five seconds). Run the included local Volcengine ASR backend; it uses the external volcengine-media skill's credentials and has passed real-provider checks with synthetic audio. Existing Listen & Find levels need no backend. See [speech integration](docs/SPEECH_PROVIDER.md) for backend setup and [Phase 4 report](docs/PHASE_4_REPORT.md) for physical-device acceptance limits.
    
    ## Run
    
    Phase 5 adds Listen & Slice at the Waterfall map pin, reusing the market scene and Unit 3 content. Listen, then swipe across a fruit using a mouse drag or touch. One gesture cuts its first available fruit; cut fruits cannot count twice in the same task. Find the correct fruit and choose Next. See [Phase 5 report](docs/PHASE_5_REPORT.md) for verification and device limits.
    
    Use Node 22 and pnpm 10.27.0:
    
    ```sh
    pnpm install --frozen-lockfile
    pnpm dev
    ```
    
    Phase 6 adds separate learning notes and offline resubmission. Start the local learning backend in another terminal with Python 3.11+: `python scripts/learning_server.py`. No extra Python packages are needed. SQLite defaults to `~/.english-adventure/learning.sqlite3`, outside Git; `--database` and `--port` override it. Vite proxies `/api/v1/` to loopback port 8788. Static hosting needs the same-origin API route configured separately. Open 鈥淟earning notes for grown-ups鈥?on the map for sync status and content observations.
    
    One anonymous device profile represents the learner; shared-device users share these observations. Completed sessions and sessions left through the map are saved. Browser storage holds at most 200 unsent sessions, with 20 sent per batch, an eight-second request timeout, and automatic retries from 15 seconds up to five minutes plus retry on reconnect/reload. Clearing site data removes unsent notes and the local profile; browser storage denial/full conditions are reported. Abrupt browser termination during an active session can lose that unfinished session. The backend is for local use only; authenticated multiuser access is not implemented. No audio, transcripts or swipe paths are saved. Review flags indicate unfinished/hinted/retried tasks, never mastery.
    
    ## Publish over HTTPS
    
    `pnpm build` writes a static site to `apps/web/dist`; serve it over HTTPS, with the speech API routed separately if Voice Match is used. Browsers expose secure-context APIs (`crypto.randomUUID` and the microphone for Voice Match) only on HTTPS or localhost. Plain-HTTP LAN pages support Tap, but the microphone will not work.
    
    - Serve `index.html` with `Cache-Control: no-cache`; the hashed files under `assets/` can be cached for a year (Phaser is its own chunk, so app upgrades do not re-download it).
    - Same-origin only: images and audio load from `/images` and `/audio` on the same host.
    - To test on a real iPad before publishing, use an HTTPS tunnel or a local certificate (for example mkcert) rather than a bare LAN IP.

    # Architecture
    
    Current milestone: Phase 8 architecture regression and performance, authorized after Phase 7. Two checkpoints cover lazy loading/viewport lifecycle and extension/regression evidence. Stop for review after Phase 8; this is the task book's final chapter.
    
    Phase 8 lazily imports the adult Composer and coalesces viewport resize callbacks with disposal cancellation. A test-only Reaction plugin runs against the real FruitWorld class (drawing mocked), public object/answer contracts and existing round loop over five restarts without Core changes. Browser lifecycle tests check canvases and managed Blob URLs return to zero across repeated scene/mechanic switches. These checks do not replace physical-device memory or latency profiling.
    
    Phase 7: Composer reads local PluginMetadata and content data, builds standard GameDefinition JSON, validates with PluginManager/Ajv, validateAdventure, ContentResolver and scoped AssetManager, then either stores JSON in localStorage, downloads it, imports it or previews through the existing React bridge. Preview has no learning callback and its completion does not write map stars. Local plugin factories remain code-owned; configuration cannot execute code or load remote plugins. Public publishing, authentication, drag editing and new game protocols are not implemented.
    
    Phase 6: runtime optionally owns a learning-core collector per engine session and passes its immutable snapshot to a host callback at completion or context disposal. Public ownership contracts include learner, game, session, curriculum, unit and target content. The host uses a pseudonymous local profile, a bounded per-session localStorage outbox and same-origin HTTP. A loopback Python/SQLite backend validates strict learning-only payloads and atomically deduplicates by session ID; learning progress is aggregated separately from rewards. Collection stores no raw input, transcript or audio. Recording facts require successful capture start; recognized facts require nonempty text above the mechanic confidence gate, including wrong words. Review flags are observations rather than mastery. Active-session crash recovery and authenticated public deployment are outside this phase.
    
    Phase 5: optional SWIPE-mode Phaser adapters collect at most 128 world-coordinate samples and InputManager clears pending gestures at enable/disable boundaries. Slice intersects path segments against up to six candidate bounds and submits only the first uncut hit through IAnswerPort. Task-local cut IDs prevent duplicates. Runtime's optional object slice operation crops the existing texture into two animated halves; FruitWorld declares SLICE without importing the mechanic or changing its scene implementation. Plugin-scoped assets include a synthetic slice cue played through AudioManager before feedback. Game Core, RuleEngine and TaskRunner are unchanged. Tap, Voice Match and Slice reuse the same scene and round/reward loop.
    
    Phase 4: Record/Done commands travel through the bridge to runtime-owned VoiceCapture. VoiceRecorder negotiates browser encoding and releases microphone tracks; SpeechService bounds the independently injected ASR adapter. HttpSpeechRecognizer uploads only encoded audio and language to a same-origin backend. The loopback Python speech service proxies Volcengine ASR using skill-managed credentials and FFmpeg pipes; no server dependency enters game-core, learning-core or mechanics. The runtime dispatches a task/session-scoped VOICE fact through InputManager; the locally registered VoiceMatch mechanic maps text to a content ID and reports through IAnswerPort. Pause/replay/restart/disposal cancel capture and discard stale results. Audio session routing returns to playback before feedback. TTS remains independent and generated prompts remain compatible. See SPEECH_PROVIDER.md for setup and real-provider verification limits.
    
    v3.2: the host shows a world map (apps/web/src/data/world.json, one pin per level, each pin names a game JSON). The monkey guide speaks through GameViewState (feedback, word) so React never reads task data early; the scene gives its counter position to the object layer (setShelf). Mechanics report answers only through IAnswerPort (submit / unrecognized); the runtime decides when answers are open, so a spoken "not heard" is never counted as wrong. The runtime picks plugins from a local catalog by id (plugin-catalog.ts) and preloads each plugin's own assets before the game can start. Audio session mode (playback vs play-and-record) is switchable for the microphone phase.
    
    Data flow (v3.1): the host loads GameDefinition and LearningContent from JSON (apps/web/src/data, content checked by parseContents) 鈫?runtime validates the supported feature subset 鈫?ContentResolver checks explicit curriculum/unit ownership 鈫?AssetManager preloads required images/audio 鈫?GameEngine validates schemas, local plugins and capabilities 鈫?learning-core creates tasks with shuffled candidates 鈫?core TaskRunner owns the round loop (present, submit, hint, next, finish) and is the ITaskView plugins read 鈫?pointer adapters feed InputManager 鈫?Tap shows the current task's candidates on TASK_PRESENTED and emits selection facts 鈫?RuleEngine evaluates once 鈫?RewardManager grants once per task 鈫?bridge publishes view state. Mechanics only decide how an answer is collected; the loop is shared, so Voice Match and Slice reuse it. React owns controls and overlays; Phaser owns drawing and world coordinates.
    
    Runtime composes the engine, local Fruit World/Tap factories, viewport, input and audio managers. Core, contracts and learning-core remain independent of React and Phaser. The scene does not evaluate answers; the mechanic contains no textbook vocabulary. Runtime gates selection until prompt playback completes and ignores stale asynchronous playback after pause, restart or disposal. Restart creates a new session and resets observations/rewards. Page hiding pauses the game.
    
    Edge TTS is a build-time asset-generation utility. Playback uses Web Audio with a same-origin HTML Audio fallback when AudioContext is unavailable. Failed playback locks selection and allows Listen to retry. Short speech captures remain in memory; Phase 6 persists learning observations separately. No persistent recording store or mastery model is implemented.
    
    Phase 2 adds a standalone Fruit World visual plugin, public object operations and runtime viewport adapter. Scenes import contracts and Phaser only. Scoped AssetManager deduplicates loads and disposes object URLs; viewport owns texture registration and canvas destruction.
    
    The design baseline is the two original documents at the repository root, with subsequent user decisions recorded in DEVELOPMENT_TASKS.md.
    
    Dependencies: React host 鈫?runtime 鈫?contracts/core/learning/scenes/mechanics/speech. Speech-core depends on contracts only. React receives no Phaser references.
    
    Phase 0 creates a temporary neutral canvas in the runtime, not a scene plugin or an English learning game. Phaser owns canvas coordinates and animation. The host owns mounting and UI. A directional bridge carries commands and state messages. Initialization checks cancellation after dynamic imports; disposal removes listeners and the canvas and requests Phaser system cleanup on its next frame. No shared mutable runtime singleton exists.
    
    No remote plugins, dependency injection container, executable content or camera support is introduced. The local speech backend is a narrow API proxy; it adds no learning database or accounts.
    
    Phase 1 freezes typed event payloads, plugin lifecycle, configuration schemas, session/restart semantics and public object interaction contracts. See game-contracts/src/game.ts. Core validates local registration and lifecycle; runtime owns content/resource readiness. Each restart allocates a new session. The user authorized autonomous checkpoint progression through Phase 3.
